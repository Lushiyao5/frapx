## Which package do I need?

frapx is split into several small packages instead of one big one. The
prefix in the package name tells you what kind of package it is — you
never need to guess:

<CardGrid stagger>
	<Card title="fx-* — effect runtimes" icon="rocket">
		Instantiate directly in your app. **[`@frapx/fx-canvas`](/frapx/packages/fx-canvas/)**
		drives a full-screen WebGL fragment shader as a background or overlay.
		This is what most people install first. **[`@frapx/fx-passes`](/frapx/packages/fx-passes/)**
		chains passes and accumulates samples for anti-aliased, motion-blurred
		video frames (WebGL2).
	</Card>
	<Card title="react-* — framework bindings" icon="puzzle">
		A thin React wrapper around an `fx-*` package. **[`@frapx/react-canvas`](/frapx/packages/react-canvas/)**
		wraps `@frapx/fx-canvas` as a `<ShaderBackground />` component and a
		`useShaderBackground()` hook.
	</Card>
	<Card title="glsl-* — GLSL snippets" icon="seti:shader">
		Plain GLSL source strings you concatenate into your **own** fragment
		shader — not a runtime, no instantiation. **[`@frapx/glsl-noise`](/frapx/packages/glsl-noise/)**
		(3D noise), **[`@frapx/glsl-flowmap`](/frapx/packages/glsl-flowmap/)**
		(flowmap decode/advection), **[`@frapx/glsl-sdf`](/frapx/packages/glsl-sdf/)**
		(2D/3D signed distance functions) and **[`@frapx/glsl-raymarch`](/frapx/packages/glsl-raymarch/)**
		(raymarching loop, shadows and camera rays) are available today.
	</Card>
	<Card title="tool-* — tools" icon="download">
		Export and production utilities built on an `fx-*` instance, not effects
		themselves. **[`@frapx/tool-capture`](/frapx/packages/tool-capture/)**
		renders deterministic 8-bit or 16-bit PNG sequences to a folder or a ZIP
		in the browser.
	</Card>
	<Card title="core — internal engine" icon="setting">
		**[`@frapx/core`](/frapx/packages/core/)** is the shared WebGL lifecycle
		host every `fx-*` package is built on. You install it transitively — as
		an `fx-*` package's dependency — and never import it directly.
	</Card>
</CardGrid>

## Quick decision table

| I want to... | Install |
| --- | --- |
| Add an animated WebGL background to a plain website | `@frapx/fx-canvas` |
| Add the same, but I'm in a React app | `@frapx/fx-canvas` + `@frapx/react-canvas` |
| Add turbulence/grain to my own fragment shader | `@frapx/glsl-noise` (needs `@frapx/fx-canvas` or your own GL setup) |
| Distort a texture with a painted flowmap | `@frapx/glsl-flowmap` (WebGL2 / GLSL ES 3.00) |
| Draw shapes with signed distance functions | `@frapx/glsl-sdf` |
| Raymarch a 3D scene with shadows, occlusion and a camera | `@frapx/glsl-raymarch` + `@frapx/glsl-sdf` |
| Export my shader as a PNG sequence for video | `@frapx/fx-canvas` + `@frapx/tool-capture` |
| Chain passes (bloom, trails) or render anti-aliased, motion-blurred frames | `@frapx/fx-passes` (+ `@frapx/tool-capture` to export) |
| Build a *different* effect runtime (not a background shader) | Nothing yet — see the [roadmap](https://github.com/kramhash/frapx) for `@frapx/fx-particles` |

Still not sure? Start with [Getting Started](/frapx/getting-started/) — it
walks through the one package (`@frapx/fx-canvas`) that covers the common case.

## Coming from `@frapx/shader` or `@frapx/runtime`?

All five packages were renamed on 2026-07-12 to this prefix scheme. No public
API changed — only package names and import paths. See the
[migration guide](/frapx/migration/) for the full old → new mapping.
